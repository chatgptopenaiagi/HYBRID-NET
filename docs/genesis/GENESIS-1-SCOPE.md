# Genesis 1 scope

Status: **ENGINEERING DECISION / milestone boundary**. Product version 0.0.1;
project status ARCHITECTURE FOUNDATION. The owner authorized a new public repository
under chatgptopenaiagi/HYBRID-NET and an initial main-branch publication when access
permits. This authority is specific to the founding milestone.

## In scope

Preserve all founding concepts as substantive, navigable documents. Define the
independent client, optional server and hybrid modes; common capability semantics;
dual executables; AIXR; six language roles; state observation; credential authorities;
SQLite/SQL Server roles; future integrations and measurable later milestones.
Record eight initial ADRs, alternatives, unresolved questions and future-agent rules.

Initialize the preferred local path without replacing existing files. Check Git,
GitHub CLI, authenticated account and target repository existence without exposing
credentials. Commit the reviewed foundation; publish when available; verify remote
identity, branch and commit. If blocked, preserve the local work and exact blocker.

Documentation integrity tooling may check required paths, links, conceptual JSON,
mission coverage and accidental credential/file inclusion. It must not be described
as testing a runtime. No personal documents, machine inventories, model exchanges or
neighboring-project source belongs in the public repository.

## Out of scope

No runtime prototype, adapter implementation, background service, AI inference,
client/server executable, installer, database installation, driver, kernel modification,
VM configuration or third-party application modification. Tiny executable experiments
are Genesis 2 work; they do not displace architectural preservation.

Do not merge, move or modify CFA, SCE, QASC, CLARA, CAE, POK, capability labs or local
model installations. Do not read their credentials to initialize this repository.
No license grant, production certification or universal proprietary-app access is
inferred from public documentation.

## Completion and continuation

Use [the acceptance checklist](GENESIS-1-ACCEPTANCE.md) and
[traceability map](FOUNDING-TRACEABILITY.md). Every capability claim must have the
appropriate evidence class. Mark publication only after authenticated read-back,
not after writing a remote URL. A successful Genesis 1 establishes a foundation;
Genesis 2 remains unimplemented until its own acceptance evidence exists.
